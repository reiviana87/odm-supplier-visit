01 · What I assumed

Where the brief left a decision open, this is what I chose and why. Correct me and I will change it.

Sample data
Built on your real report

Every string, photo, certificate, Q&A and appendix caption comes from the HEBEI HUATONG report you uploaded (GSO-2608001x00). Nothing is invented, so the layout is stress-tested against real content length.

Editor shape
Three panes, not a wizard

Section navigator (210 px) · workspace · a rail (320 px) that is either Sources or the AI Assistant. Shell minimum is 1280 px, so the writing column holds ~530 px with the rail open and ~840 px closed. A wizard would fight the real workflow, which is non-linear.

Completion
Derived, never stored

Completion % is computed from 13 section predicates (see §06). It cannot drift from reality, and the dashboard, list and editor all read the same number.

Supplier data
Linked, then frozen

§2 and §7 read the supplier record — never re-typed. On report creation a snapshot is frozen; if the record changes later the editor offers “Refresh snapshot” rather than silently rewriting a signed report.

Mobile
Capture only

Visit Mode does photos, notes, observations and sources. It never tries to be the editor. Read-only report view so you can check what is still missing while you are still in the factory.

Deviation from the design system
Photos stay true colour

Industry duotones photography into the steel accent. Nothing here is duotoned: appendix work requires judging real factory colour, so photo cards keep the hairline frame and drop the wash, and the login cover is a knocked-out product plate on the technical grid rather than a photograph.

07 · Appendix layout — the 6.5 cm question

The requirement was not changed. It is surfaced as arithmetic the user can see and decide on.

A4 portrait 21.0 × 29.7 cm, margins 2.0 cm → text box 17.0 × 25.7 cm
One alternating pair = photo row (h) + caption row (0.55 cm)
At h = 6.5 cm → pair height 7.05 cm → 3 pairs = 21.15 cm fits; 6 pairs = 42.3 cm does not
12 alternating rows (6 photo rows) exceeds the page by 16.6 cm
UI Layout & Preview shows the template geometry, lets the user move image height and rows per page, and states the conflict in centimetres with the maximum that does fit. The export proceeds either way — the uploaded DOCX template has final say on pagination, and the preview mirrors what it will produce.

08 · System states

Factory connections in China are unreliable. Losing entered work is the only unacceptable failure.

Saving / Saved
Dot + timestamp in the editor header. Never a blocking spinner.
Offline
Top bar switches to “Offline — n changes queued”. Visit Mode shows the queue count. Writes go to local storage first.
Uploading
Per-photo progress on the card; the grid stays interactive. Failed uploads keep the card with a Retry action.
AI running / failed
Inline spinner in the modal that requested it. On failure the user's text is untouched and Retry is offered.
DOCX running / failed
Four named stages with a progress bar. On failure, which stage failed and which section caused it.
Incomplete export
Amber pre-flight listing empty placeholders and uncaptioned photos. Export is allowed anyway.
No transcript / no supplier
AI actions that need a source are disabled with the reason, not hidden.
Empty states
Suppliers, reports, photos and conclusion each state what is missing and offer the one action that fixes it.

09 · Build notes

Data
Tables to create

suppliers, supplier_contacts, supplier_certificates, supplier_files, reports, report_sections, report_snapshots, observations, qa_items, target_products, photos, sources, findings, templates, template_mappings, members. Photos carry section, position, caption, ai_caption, ai_confidence, state.

Autosave
Section-scoped, debounced

Patch one section at a time (400 ms debounce), optimistic UI, queue in IndexedDB when offline, replay on reconnect. Keep a version row per save so “history” and AI rollback are free.

DOCX
Template-driven, server-side

Fill the uploaded template rather than generating a document: text placeholders by name, three image regions built as tables. Re-scan the DOCX on upload to detect placeholders and flag unbound ones on the mapping screen.

Extensible
Left room for

Supplier scorecards and comparison (supplier detail already tabbed), action item tracking (observations carry priority), the cross-report knowledge base (Assistant page already has the surface, marked Preview), and approval workflow (In Review status is live).
